# TF版本排查与下一步

## 升级前观察到的事实

- 原练习场景此前短程导航成功一次。恢复后等待一段时间，再测相同目标返回ABORTED，最大反馈恢复次数21。
- 控制器反复报告无法把机器人位姿变换到全局路径坐标系。独立新建的TF查询仍能得到位姿；这不能证明控制器内部缓存正常。
- 本机ros-humble-tf2、ros-humble-tf2-ros、ros-humble-tf2-ros-py、ros-humble-tf2-geometry-msgs都是0.25.23。
- 官方0.25.24更新日志包含waitForTransform与testTransformableRequests间ABBA死锁的修复。相关症状与本机相符，暂作待验证假设；未取得本机线程堆栈，尚不能认定唯一原因。
- 本机当前软件源提供上述包0.25.24；模拟安装只升级这4包，没有新装或删除包。

ABBA死锁指两个执行线程分别持有对方需要的锁，又互相等待。进程可能仍在、其他部分仍打印日志，但相关数据处理无法继续。它与“地图中没有map这个名字”的普通配置错误需要区别排查。

来源：[官方0.25.24更新日志](https://github.com/ros2/geometry2/blob/0.25.24/tf2_ros/CHANGELOG.rst)、[问题992](https://github.com/ros2/geometry2/issues/992)、[问题995](https://github.com/ros2/geometry2/issues/995)。问题报告用于寻找线索，不代替本机验证。

## 学生操作：窗口2

本轮Gazebo、RViz和导航程序已经停止。执行：

```bash
sudo apt-get install --only-upgrade \
  ros-humble-tf2 ros-humble-tf2-ros \
  ros-humble-tf2-ros-py ros-humble-tf2-geometry-msgs
```

`sudo`提供安装权限；`install`可以更新已安装包；`--only-upgrade`限制为升级已有的指定包。先前的`apt-get -s`只计算计划，没有安装软件。本命令才执行实际更新。系统询问是否继续时核对计划；若要求密码，在本机输入，输入时通常不显示字符。

执行后检查：

```bash
dpkg-query -W ros-humble-tf2 ros-humble-tf2-ros ros-humble-tf2-ros-py ros-humble-tf2-geometry-msgs
```

按当前软件源，版本应以0.25.24开头。若安装失败，保留完整错误，不继续叠加启动仿真。

## 升级后由助手代做的重复验证

1. 保存实际安装后的版本；重新启动相同练习地图、世界、参数和已知初值。
2. 复测原短目标，再测试跨区域与绕障目标，保存真实action结果和日志，失败即停止分析。
3. 加入等待后复测，以覆盖此前“刚启动成功、等待后失败”的触发方式。测试通过只支持已测试条件，不能证明任何时长下都稳定。
4. 稳定后再教学讨论正式场景选择、白格假设与路线设计；候选生成和重复运行可继续代做。

升级前证据目录：`validation/automatic_v0_20261029_135522/`，包含版本、模拟安装计划、原始action、TF探测、失败日志和进程清理记录。以上操作说明在升级前写入。

## 升级后的实际进展

用户已执行升级；助手查询确认4包均为0.25.24，版本保存于`validation/tf2_versions_after_20261029.txt`。第一轮原短目标成功、跨区域Action成功但停靠位置仍待核验，绕障目标达到120秒测试时限后取消。随后一次SIGINT使全部跟踪子进程约10.24秒内退出，无需额外强杀。

另一次有效复测先核实TF与生命周期就绪，再保持同一组节点静置300.009秒；原短目标Action成功，恢复次数0。自动恢复中另有一次初值未生效的轮次，已标为无效并重做，没有当作成功稳定性证据。详见[升级后验证汇总](验证汇总_20261029.md)。

当前证据支持本轮运行和退出行为改善，仍未证明所有等待时长、场景和负载下都稳定。下一步进入代价地图、规划终点和到达判定的教学，不自动修改参数来掩盖位置差距或绕障失败。
