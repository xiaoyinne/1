# 第四周交付：Hilti 局部地图仿真环境

## 已完成到什么程度

已将本人FAST-LIO输出PCD中的局部高度切片转换为Nav2二维地图，并生成位置一致的Gazebo静态碰撞体。在人工平地上运行TurtleBot3、AMCL、Nav2，已记录短程、手动目标及一次绕障执行成功，也保留超时和TF故障记录。

这是可复现的局部仿真原型。源点云中的真实地面、坡度、楼层和原始障碍高度尚未恢复；高度段的物理合理性尚未证明。它适合用于学习地图接口和导航链路，不能作为真实Hilti环境可通行性的证据。

培养方案中的第四周产出是地图仿真环境；第五周的A*、DWB完整巡检闭环和视频尚未完成。当前规划器use_astar=False，定位为AMCL并提供已知初始位姿，未接入第二周的重定位模块。

## 本机恢复与复测

环境：WSL Ubuntu 22.04、ROS2 Humble、Gazebo Classic 11；已安装nav2_bringup、turtlebot3_gazebo。记录版本：nav2_bringup 1.1.20、tf2/tf2_ros 0.25.24。使用软件渲染、非组合节点、仿真时间和5 FPS RViz。

窗口1执行：

```bash
bash /mnt/c/Users/Administrator/Documents/Codex/2026-10-26/https-github-com-xiaoyinne-1-git-2/outputs/week4_learning/restore_hilti.sh
```

窗口2执行下列命令。最后一条会提供已知初值，并实际发送一个0.7米的短目标，机器人会移动：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=0
cd /mnt/c/Users/Administrator/Documents/Codex/2026-10-26/https-github-com-xiaoyinne-1-git-2/outputs/week4_learning
python3 wait_then_check.py --run --wait-seconds 0
```

此脚本要求机器人仍在出生位置，不能对已经走远的机器人反复运行以重设位置。wait-seconds=0仅作恢复检查；300才表示核实就绪后静置5分钟。本轮恢复已由助手完成，无需立即重复运行。

若整个目录换到其他位置，先进入该目录，再运行bash ./restore_hilti.sh和上述Python命令；启动器通过自身位置查找地图及RViz配置。使用已生成的地图和世界启动仿真，不要求原PCD在线。

窗口3是RViz，窗口4是Gazebo。正常结束时，窗口3 File→Save Config保存显示设置，再在窗口1按Ctrl+C，等待节点退出。

## 从PCD重新生成

在包含本说明的目录执行。需要系统Python的numpy、matplotlib、Pillow、PyYAML。将--pcd后面的路径换成实际源文件位置：

```bash
python3 -s project_slice.py --pcd /mnt/d/chromeDownload/fastlio_hilti_fixed_20261008.pcd --z -1.5 -0.8 --min-points 5
python3 -s export_nav2_map.py
python3 -s build_world.py --height 1.0
```

本命令会重新写出投影、地图及世界；应在仿真关闭时重新生成并在下次启动加载。白格只表示选中高度段的点数不足阈值，没有通过激光射线验证自由空间。没有添加外围墙、形态学补洞或删除障碍来换取导航成功。

投影数组行号从最小Y起算，PGM图片行号从上向下，因此导出要翻转上下行序。栅格碰撞体位于origin+(index+0.5)×resolution，使用格中心，尺寸为一个完整栅格。

新增导出脚本已在work/resume_export_check单独输出验证：YAML语义与原件相等、PGM像素完全相等；原仿真文件保持不变。碰撞体反算网格后与393个占据格一致，visual数量也为393。
