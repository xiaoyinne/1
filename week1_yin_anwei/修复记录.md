# Hilti 2022 Hesai 数据适配与保存修复

数据：`exp18_corridor_lower_gallery_2.bag`，已转成 `/home/yaw/ros2_bag`。

## 问题与修改

1. `laserMapping.cpp` 中用于累计 `pcl_wait_save` 的代码被块注释禁用，导致退出保存没有数据。已恢复累计，并让退出保存使用配置的 `map_file_path`，为空时才回退到源码目录 `PCD/scans.pcd`。
2. 本 bag 点云的 `timestamp` 为 FLOAT64 绝对秒时间，与消息 header 在同一时间轴。实测每帧点时间跨度约 0.100 秒。此前按扫描角估算时间会忽略真实时间。现在按 `(timestamp - header_time) * 1000` 转换为 FAST-LIO 的帧内毫秒时间，`timestamp_unit` 设为 0。
3. 此前套用 Velodyne 默认外参，旋转为单位阵、平移为 `[0,0,0.28]`，不符合本数据集。现在使用官方 Hilti 2022 标定：
   - `T_imu_pandar` 平移：`[-0.001, -0.00855, 0.055]`
   - 四元数 xyzw：`[0.7071068, -0.7071068, 0, 0]`
   - 旋转矩阵：`[[0,-1,0],[-1,0,0],[0,0,-1]]`
4. 窄走廊首帧中，大于 0.7 米的点有 20,804 个，大于 2 米的点只有 2,252 个。近距阈值从 2 米改为 0.7 米，地图/表面体素从 0.5 米改为 0.2 米。
5. 修正后的原速回放仍不稳定；半速回放完整序列没有出现 `No Effective Points!`。这说明播放和处理速度影响结果，但此次未通过丢包计数单独确认机制。

标定来源：[Hilti-Research 官方数据集标定文件](https://huggingface.co/datasets/Hilti-Research/hilti-slam-challenge-2022/blob/main/calibration/calibration_files/lidar_calibration.yaml)。

旧完整点云跨度约为 `[20418, 6874, 14630]` 米，已严重发散，不能作为合格建图结果。

## 正常运行与保存

先启动 FAST-LIO：

```bash
source /opt/ros/humble/setup.bash
source /home/yaw/ros2_ws/install/setup.bash
ros2 launch fast_lio mapping.launch.py config_path:=/home/yaw/ros2_ws/src/FAST_LIO/config config_file:=hesai.yaml use_sim_time:=true rviz:=false
```

另一个终端播放一次数据，不加 `--loop`：

```bash
source /opt/ros/humble/setup.bash
ros2 bag play /home/yaw/ros2_bag --clock --rate 0.5 --topics /hesai/pandar /alphasense/imu
```

播放结束后，在 FAST-LIO 终端按一次 Ctrl+C，等待正常退出与保存日志。配置默认输出 `/home/yaw/ros2_ws/fastlio_map.pcd`。需要保留此前结果时，应先复制到其他名称，或为新运行指定其他输出路径。

修复的是退出保存；`map_save` 服务仍使用另一个地图发布缓存，此次没有验证该服务。
